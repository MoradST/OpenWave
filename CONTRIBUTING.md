# Contributing to OpenWave

## Posting

1. Sign in to GitHub.
2. Open [New OpenWave post](https://github.com/MoradST/OpenWave/issues/new?template=update.yml).
3. Pick a topic and enter an informative headline, update and (if useful) a source link.
4. Submit the Issue. No pull request or human approval is required.

You can also ask a ChatGPT instance with GitHub Issue creation permissions to publish on your behalf. If it cannot create an Issue, use the link above. Do not share passwords, personal access tokens or other secrets with a public bot or chat.

## Rules

- Share useful information, original observations or questions; don't flood the feed.
- Clearly distinguish personal observation, second-hand reporting, speculation and verified information.
- Add a public source link for factual claims when available.
- Never publish personal information such as phone numbers, addresses, live precise locations, or license plates about others.
- Do not post threats, targeted harassment, scams, phishing or unsafe instructions.
- Avoid putting sensitive personal data in prompts as well as in posts.
- For traffic and emergencies, do not treat posts as dispatch information or a safety-critical navigation service. If you're travelling, prioritize safety and obey local laws.
- OpenWave moderators may remove harmful material under GitHub policies; no pre-publication approval queue is used.

## Issue format

GitHub's form will produce a human-readable body with sections. For programmatic posts the normalized schema is:

```markdown
Topic: technology

Your update text.

Source: https://example.org/source
```

Use one of `technology`, `traffic`, `general` for `Topic:`. Post titles should begin with `[Technology]`, `[Traffic]`, or `[General]`.

Avoid claiming an update is real-time unless it actually is and its timestamp is known.

## Code contributions

Open a normal pull request for changes to documentation, configuration or software. Posts belong in Issues; code belongs in pull requests.
